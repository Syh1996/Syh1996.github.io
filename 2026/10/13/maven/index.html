Maven 下载与配置完全指南

Maven 是 Java 开发的核心构建工具，安装前需要先确保系统已安装 JDK 8 及以上版本 ，可通过命令行执行 java -version 确认。Maven 本身没有安装程序，下载压缩包解压后配置环境变量即可使用。

一、下载 Maven

官方下载地址 ：https://maven.apache.org/download.cgi

这是 Apache Maven 项目唯一指定的下载入口，页面会自动显示当前最新稳定版。截至 2026 年 5 月， 最新稳定版本为 3.9.16 ，另有预览版 4.0.0-rc-6。

下载时注意：

  • Windows 用户选择 apache-maven-3.9.x-bin.zip
  • Linux/macOS 用户选择 apache-maven-3.9.x-bin.tar.gz

⚠️ 务必下载 bin 包，不要下载 src 源码包。

下载后解压到合适位置， 路径不要包含中文和空格 ，例如 D:\dev\maven\apache-maven-3.9.16。

二、配置环境变量

Windows

  1. 新建系统变量 MAVEN_HOME
    右键「此电脑」→「属性」→「高级系统设置」→「环境变量」→ 在「系统变量」中点击「新建」：
    • 变量名：MAVEN_HOME
    • 变量值：Maven 解压目录，如 D:\dev\maven\apache-maven-3.9.16
  2. 编辑 Path 变量
    在「系统变量」中找到 Path，点击「编辑」→「新建」，输入 %MAVEN_HOME%\bin，然后一路确定保存。

七、settings.xml 完整结构与常用标签

settings.xml 是 Maven 的全局配置文件，管的是「从哪下、下到哪、用什么账号」，与具体项目无关。

文件位置（两个位置都可放，用户级优先级更高）：

级别 路径 说明
全局 ${MAVEN_HOME}/conf/settings.xml 影响本机所有用户
用户 ~/.m2/settings.xml（Windows：C:\Users\用户名\.m2\settings.xml） 只影响当前用户，推荐

💡 建议改用户级 ~/.m2/settings.xml，这样以后升级 Maven 换目录时配置不会丢。

settings.xml 标签速查

标签 作用 常用值 / 说明
<localRepository> 本地仓库目录 如 D:\dev\maven\repo；不配默认 ~/.m2/repository
<interactiveMode> 是否允许交互输入 true / false
<offline> 离线模式 true 时只用本地已有依赖（断网/省流量）
<mirrors> 镜像配置（最重要） 里面放 <mirror>，可配多个
<mirror><id> 镜像唯一标识 自定义，如 aliyunmaven
<mirror><url> 镜像仓库地址 见「九、仓库地址大全」
<mirror><mirrorOf> 拦截哪些仓库 central、*、!私服id 等，见下表
<servers> 私服认证账号 <id> 必须与 pom 里 repository 的 id 一致
<proxies> 网络代理 内网环境用
<profiles> 环境参数集合 可配 JDK、编码、仓库等
<activeProfiles> 显式激活 profile 如 <activeProfile>jdk-8</activeProfile>
<pluginGroups> 插件组（可省略 groupId 调插件） 一般不用改

<mirrorOf> 常用写法（易踩坑）

写法 含义
central 只代理中央仓库（最常用）
* 代理所有仓库（⚠️ 会连私服也代理掉，私服会失效）
external:* 代理所有非 localhost / 非文件的仓库
*,!nexus-releases 代理所有，但排除私服 id（推荐用法）
repo1,repo2 只代理指定 id 的仓库

⚠️ 如果把 <mirrorOf> 写成 *，而公司私服也在 pom 里配置了，那么私服请求会被镜像劫持，导致「下载不到内部包」。此时必须用 *,!私服id 排除。

八、pom.xml 核心标签详解

pom.xml 是项目级配置，管的是「这个项目叫什么、依赖谁、怎么打包」。一个最小可用的 pom：

xml

pom.xml 标签速查

标签 作用 说明
<modelVersion> POM 版本 固定 4.0.0
<parent> 继承父工程 继承依赖版本、插件配置
<groupId> 组织/公司标识 如 com.tencent.oa
<artifactId> 项目/模块名 如 tencent-rpt-server
<version> 版本号 SNAPSHOT 为快照版（可覆盖），不带为正式版
<packaging> 打包类型 jar（默认）/ war / pom（父工程）
<properties> 变量定义 用 ${xxx} 引用，集中管版本
<dependencyManagement> 依赖版本管理 只声明版本不引入；子模块引时不写版本
<dependencies> 项目依赖 真正的依赖列表
<scope> 依赖作用域 见「十、依赖作用域」
<optional> 可选依赖 true 时不传递给下游项目
<exclusions> 排除传递依赖 解决冲突/去冗余
<build> 构建配置 内含 <plugins>、<resources> 等
<finalName> 产物名 打成 demo.jar
<plugins> 构建插件 如 spring-boot-maven-plugin
<repositories> 依赖下载仓库 私服/第三方仓库
<distributionManagement> 发布目标仓库 deploy 时推到哪
<profiles> 环境配置 多环境（dev/test/prod）打包
<modules> 子模块列表 父工程用，见「十三、多模块工程」

<distributionManagement>（发布用）

十、依赖作用域（scope）说明

<scope> 决定依赖在哪些阶段可见、是否打进最终包。

scope 编译期 测试期 运行期 打进包 典型场景
compile（默认） ✅ ✅ ✅ ✅ 大多数依赖，如 spring-web
provided ✅ ✅ ❌ ❌ lombok、servlet-api（容器已提供）
runtime ❌ ✅ ✅ ✅ JDBC 驱动 mysql-connector-java
test ❌ ✅ ❌ ❌ junit、mockito、spring-boot-starter-test
system ✅ ✅ ✅ ❌ 本地 jar（需写 systemPath，不推荐）
import — — — — 仅用于 <dependencyManagement> 导入 BOM

十一、常用 Maven 命令速查

命令 作用
mvn -v 查看 Maven / JDK 版本
mvn clean 清理 target 目录
mvn compile 编译主代码
mvn test 跑单元测试
mvn package 打包（jar/war）
mvn install 打包并安装到本地仓库（供本机其它项目引用）
mvn deploy 打包并发布到远程仓库（私服）
mvn clean package -DskipTests 打包但跳过测试

mvn clean package -Pprod 激活 prod profile 打包

mvn clean package -U 强制更新 SNAPSHOT 依赖（解决「拉不到最新快照」）
mvn clean package -o 离线构建（只用本地仓库）
mvn clean package -X 打开 debug 日志（排查问题用）
mvn dependency:tree 打印依赖树（排查冲突）
mvn dependency:tree -Dincludes=groupId:artifactId 只看指定依赖的来源
mvn dependency:analyze 分析「用了没声明 / 声明了没用」的依赖
mvn help:effective-pom 查看合并父工程后的最终 pom（排查看不到父配置）
mvn help:effective-settings 查看合并后的最终 settings
mvn versions:display-dependency-updates 列出可升级的依赖版本
mvn archetype:generate 生成项目骨架
mvn spring-boot:run 直接启动 Spring Boot 应用

生命周期简述

mvn package 会自动依次执行前面所有阶段（validate/compile/test 等），所以一般不用单独跑 compile。

手段 适用场景

4. 常见报错对照

报错 原因 处理
Could not resolve dependencies 仓库没有该版本 / 网络不通 换镜像源、-U 强制更新
Non-resolvable parent POM 父工程拉不到 检查父工程是否已 install 或镜像能否访问
NoSuchMethodError / ClassNotFoundException 依赖冲突（编译期一个版本、运行期另一个） dependency:tree 找冲突，排除旧版本
Artifact has not been packaged yet 多模块构建顺序问题 加 -am 一起构建
401 Unauthorized 私服账号密码错 检查 settings.xml 的 <server>
was cached in the local repository 快照缓存过期 加 -U 强制更新
invalid LOC header / jar 损坏 下载中断 删掉本地仓库对应目录重新下

十四、常见问题 FAQ

Q1：改了 settings.xml 不生效？

  • 确认改的是 IDEA 里 User settings file 指向的那个（IDEA 可能覆盖了默认路径）；
  • IDEA 里勾选 Settings → Maven → Always update snapshots 或执行 Reload All Maven Projects；
  • 命令行执行 mvn help:effective-settings 看最终生效的配置。

Q2：依赖明明下了却报找不到？

  • 检查是否被 <scope>provided / test</scope> 限制；
  • 检查是否被 <optional>true</optional> 且你是下游项目；
  • 执行 mvn dependency:tree 确认是否真的引入了。

Q3：SNAPSHOT 更新不及时？

  • 加 -U 强制更新：mvn clean package -U；
  • 或删掉本地仓库中对应 SNAPSHOT 目录后重新构建；
  • IDEA 中执行 Settings → Maven → Always update snapshots。

Q4：IDEA 右侧 Maven 面板不显示 / 依赖爆红？

  • 右键 pom.xml → Add as Maven Project；
  • 检查 Maven home path 是否指向正确；
  • 删掉 .idea 目录重新导入项目。

Q5：想跳过测试但还想编译测试代码？

  • -DskipTests：编译测试代码，但不执行（推荐）；
  • -Dmaven.test.skip=true：连测试代码都不编译（更快）。

Q6：本地仓库里一堆 .lastUpdated 文件导致下载失败？

.lastUpdated 表示「上次下载失败」，Maven 在超时周期内不会重试。清理方法：
